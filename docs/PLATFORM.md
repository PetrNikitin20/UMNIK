# Образовательная лаборатория Петра Никитина

Автор: Никитин Петр Владимирович, к.пед.н., доцент, доцент кафедры искусственного интеллекта Финансового университета.

## Что реализовано

Личный сайт и многодисциплинарная образовательная платформа используют одно приложение и одну базу D1. УМНИК сохранен как первый модуль. Второй работающий модуль — планирование эксперимента. Это авторские учебные практикумы; каталог не объявляется официальным учебным планом университета.

| Путь | Назначение |
|---|---|
| `/` | Личный сайт автора; на подключенном хосте `edu.*` — образовательный кабинет |
| `/about` | Личный сайт автора независимо от хоста |
| `/education` | Единый вход и кабинет |
| `/education?view=catalog` | Каталог и самостоятельный выбор дисциплин |
| `/education/courses/research-seminar` | Учебный научный семинар |
| `/education/courses/data-analysis` | Анализ данных: исследовательский практикум |
| `/education/courses/python-research` | Python для исследовательского проекта |
| `/education?view=competencies` | Оценки, динамика и карта связей дисциплин |
| `/education?view=teacher` | Задания, оценки, аналитика и отчетность |
| `/simulators/umnik?assignment=research-umnik` | Исходная рабочая тетрадь УМНИК |
| `/simulators/experiment?assignment=data-experiment` | Протокол эксперимента по анализу данных |

Каталог стартует с трех дисциплин и трех заданий. У каждой дисциплины может быть несколько заданий; один симулятор используется в разных дисциплинах с отдельными работами и критериями. Администратор добавляет дисциплины и учетные записи. Преподаватель настраивает задания только в назначенных ему дисциплинах.

## Порядок работы

Студент входит с прежними данными УМНИК, меняет временный пароль при необходимости, выбирает дисциплины в каталоге и открывает задания. Исходный научный семинар заранее добавлен в план существующих студентов, чтобы сохранить доступ к УМНИК. Остальные дисциплины выбираются самостоятельно.

Изменения сохраняются с оптимистической проверкой версии. Перед закрытием вкладки с несохраненными изменениями появляется предупреждение. Отправка преподавателю фиксирует конкретную версию внутри платформы и не отправляет заявку в Фонд-М. После новых правок нужна повторная отправка. Закрытое задание или дисциплина вне плана допускает чтение сохраненной работы; редактирование закрывается сервером.

В планировании эксперимента студент заполняет вопрос, гипотезу, данные, разделение выборки, baseline, метрику, протокол и план интерпретации. Ссылка на код необязательна, поддерживается HTTPS. Проверка полноты использует длину текста и не подтверждает научное качество. Содержательную оценку дает преподаватель. Примеры обозначены как учебные; отсутствие измерений указывается прямо.

Для связи дисциплин студент выбирает свою сохраненную работу другого курса и объясняет ее использование. Преподаватель отмечает перенос после проверки двух актуальных отправленных работ. Для этого ему нужны права на обе дисциплины; администратор имеет общий доступ. Сама ссылка и участие в двух курсах не доказывают перенос знаний.

## Роли

- **Студент:** свои дисциплины, работы, история, оценки и учебная активность.
- **Преподаватель:** студенты, работы, оценки и выгрузки в пределах назначенных дисциплин. Назначать себе новые права нельзя.
- **Администратор:** все дисциплины, назначения преподавателей, новые учетные записи, общая отчетность и полный учебный архив.

Существующие ФИО, логины и хеши паролей не меняются при обновлении. Пароль новой учетной записи показывается администратору один раз; он не включается в журнал. Студент обязан его заменить. Файл исходных временных доступов остается закрытым локальным артефактом и не публикуется в репозитории.

## Оценки и образовательные метрики

Версия общей шкалы: `competencies-v1`, уровни 0–4. Компетенции: постановка задачи, работа с данными, планирование эксперимента, воспроизводимое программирование, интерпретация результата, ценность исследовательского продукта.

| Балл | Значение |
|---|---|
| 0 | Действие не продемонстрировано |
| 1 | Решение выполнено с существенной помощью |
| 2 | Базовое решение |
| 3 | Самостоятельное обоснованное решение |
| 4 | Обоснованный перенос в новую задачу |

У каждой оценки есть компетенция, этап (входной/итоговый), версия работы, версия шкалы и симулятора, преподаватель, дата и конкретное обоснование. Оценки добавляются в историю; новые записи не стирают прежние. Дата и время хранятся в UTC, интерфейс показывает Москву.

Текущая итоговая оценка относится к актуальной версии работы. Для карты дисциплин берется последняя актуальная итоговая оценка студента по компетенции в дисциплине. В карточке уровень — лучший из этих результатов, а не доказательство одинакового владения во всех контекстах. Исторические оценки остаются доступными.

Динамика сопоставляет входную и итоговую оценку той же работы по одной шкале. Изменение оценки одной версии может отражать повторное оценивание; для исследования развития нужны сопоставимые задания, разные этапы работы и контроль условий. Отсутствие входной оценки не заменяется нулем. Баллы разных шкал не сравниваются автоматически.

Сводка преподавателя показывает число оцененных студентов, распределение баллов 0–4, число парных оценок, повышение/сохранение/снижение балла и подтвержденные переносы. Повторные оценки одного студента в дисциплине не увеличивают число участников. Если связанная исходная работа изменена, старое подтверждение переноса остается историческим.

Учебная активность собирается отдельно: сохранения, проверки УМНИК, отправки, просмотр примеров и приблизительное активное время. Учитывается видимая вкладка с фокусом и недавними действиями. Клиентские интервалы ограничены 30 секундами, повторы события с тем же ID не суммируются. Это оценка процесса, не мера знаний и не основание для автоматического балла. Старые действия до обновления не придумываются задним числом.

LLM продолжает давать рекомендации УМНИК только по согласию студента. Она не выставляет оценки компетенций, не прогнозирует выдачу гранта и не создает фиктивные отказы. Серверный ключ и квоты Groq сохраняются в прежней среде.

## Отчетность

CSV: работы и версии, запись на дисциплины, оценки компетенций, учебные события, исследовательская выгрузка. Период применяется к событиям и оценкам; обе даты включены целиком по московскому календарю. Для записи и работ показывается текущее состояние.

Исследовательская выгрузка содержит устойчивые псевдонимы участников, работ и оценщиков, коды заданий, версии, этапы и баллы. ФИО, логины, тексты работ и свободные комментарии в нее не входят. Псевдонимизация не является гарантией невозможности повторной идентификации по совокупности признаков. Выгрузки доступны только авторизованным преподавателям в их области доступа.

Максимум CSV — 10 000 строк; экранный список работ — 3 000, оценок — 10 000. При росте объема нужны пагинация и потоковые выгрузки. Полный учебный архив JSON доступен только администратору, включает обе версии хранения работ и журналы, исключает пароли, сессии и серверные секреты. Он не заменяет резервную копию D1 и не импортируется автоматически.

## Хранение и сохранение прежнего УМНИК

Миграции схемы: `0001_clumsy_sway.sql`, затем `0002_curvy_deathstrike.sql`. Они не удаляют пользователей или учебные записи. Старым записям УМНИК добавляется постоянный `work_key=umnik-main`; уникальность версии теперь определяется пользователем и контекстом задания. Номера и содержимое исходных версий сохраняются. Дополнительные задания УМНИК имеют независимые ключи.

Каталог, назначения администратора и связь старых работ инициализируются отдельно от DDL идемпотентной транзакцией данных. Старые заявки связываются с `research-umnik`; новые модули используют `learning_works` и `learning_revisions`. Прежние проверки и комментарии УМНИК остаются в исходных таблицах. В старой панели администратора показывается исходная заявка; все задания доступны в общей панели.

Инструкцию, симулятор и набор компетенций нельзя менять после начала работ: для иной постановки создается новое задание. Учебный срок, название и доступ можно уточнять. Оценки и события сохраняют свои версии; данные разных редакций не объединяются без проверки сопоставимости.

Для нового симулятора нужно реализовать серверную валидацию, форму и работу с общими версиями, отправкой, событиями и оценками; зарегистрировать новую запись в реестре модулей. Одного названия в каталоге недостаточно. Текущий журнал использует собственную схему событий; полная совместимость с xAPI/LRS не заявляется.

## Домен и последующее развитие

**Обновление от 15.10.2026:** после повторной публикации оба домена и HTTPS получили статус «активен». В проверочном браузере открылись личный сайт, кабинет и практикум; проверка из пользовательской российской сети без VPN пока не завершена. Для независимого российского размещения подготовлена [конфигурация VPS](RU_HOSTING.md). Новый сервер пока не оплачен и не создан; DNS по-прежнему указывает на Sites.

Выбранные адреса: `petr-nikitin.ru` — личный сайт, `edu.petr-nikitin.ru` — образовательная платформа. Домен зарегистрирован в Beget 14 октября 2026 года до 14 октября 2027 года; за регистрацию на один год списано 199 ₽. DNS обслуживается в Beget, приложение и база остаются на действующем размещении Sites. Дополнительный VPS или виртуальный хостинг Beget для этой схемы не требуется.

Для основного имени заданы A-записи `162.159.143.30` и `172.66.3.26`, для `edu` — CNAME `custom-domains.chatgpt.site.`. Четыре TXT-подтверждения внесены с актуальными значениями, полученными для существующих подключений Sites. Публикация DNS и проверка HTTPS завершаются сервисами размещения; новые адреса распространяются среди студентов после успешной проверки обоих доменов. Технический адрес приложения остается доступен на время подключения. Старые записи отмененной попытки ClouDNS повторно не используются.

Оба имени могут обслуживаться одним приложением и базой. На `edu.*` главная страница показывает кабинет; `/about` сохраняет доступ к сайту автора. Учетные записи общие, cookies сессии привязаны к конкретному хосту. После подключения домена предпочтительную ссылку входа следует распространять на образовательный адрес.

При расширении платформы: отдельные потоки/группы и правила записи, дополнительные модули, версионируемые предметные рубрики, входные/итоговые сопоставимые задания и исследовательские протоколы. Перенос в другую облачную среду и платные ресурсы не создавались автоматически. Облачное расписание новостей остается отдельной настройкой владельца; без его привязки не считается включенным.

## Проверки

`node scripts/test-rules.mjs` — правила УМНИК, московские даты, RSS и сопоставление оценок.

`python tests/api-smoke.py --calendar-fixture` — сохранение исходного УМНИК и права доступа.

`python tests/platform-api.py` — отдельная localhost БД с вымышленными пользователями: выбор дисциплин, роли, изоляция работ, конкурирующие записи, оценки, перенос и выгрузки. Скрипты не запускаются против рабочей базы и не включают данные реальных студентов.
