# Российское размещение образовательной лаборатории

Дата подготовки: 15 октября 2026 года. Это готовая конфигурация переноса, а не подтверждение уже работающего российского сервера.

## Причина и схема

Домен сам по себе не меняет хостинг. Сейчас DNS `petr-nikitin.ru` и `edu.petr-nikitin.ru` указывает на Sites/Cloudflare. На пользовательском скриншоте — отказ защиты `chatgpt.site`; при отдельной проверке — HTTP 403/1010, во встроенном браузере — страница платформы «Здесь нет сайта». Сертификаты выпущены, но подключение хостов остается в состоянии `active_redeploying`. Эти наблюдения не устанавливают единственную причину отказа и не доказывают региональную блокировку.

Целевая схема: DNS Beget → публичный IPv4 российского VPS → Caddy с HTTPS → Next.js/Node 24 → SQLite в постоянном Docker volume. Браузер загружает код и стили с самого сайта. Вход, формы, версии работ, дисциплины, метрики и отчеты не требуют ChatGPT или внешней LLM. Groq используется отдельно и только при согласии студента; ошибка API не мешает сохранению и проверке по тетради.

Один VPS не дает абсолютной гарантии доступности. Подготовлены перезапуск после остановки процесса и перезагрузки хоста, проверка базы, выход для перезапуска при трех неудачных проверках после прогрева, ежедневные копии базы и ротация журналов. Для отказа всего дата-центра нужен отдельный резервный узел; в этот пакет он не входит.

## Сервер и расходы

Рекомендуемый старт: Linux x86-64, 2 vCPU, 4 ГБ RAM, от 40 ГБ SSD, публичный IPv4, доступ SSH. Регион — Россия. Не нужен платный ispmanager. Домен остается в Beget, его повторная покупка не нужна.

На 15.10.2026 кабинет Beget сообщает об отсутствии свободных VPS во всех регионах. Каталожная цена 2 vCPU / 4 ГБ / 40 ГБ — 33 ₽/день, IPv4 дополнительно 5 ₽/день, итого 38 ₽/день; наличие не подтверждено. Источник: https://beget.com/ru/vps .

Публичный конфигуратор Timeweb Cloud в Санкт-Петербурге показывает Premium Cloud-50: 2 vCPU / 4 ГБ / 50 ГБ и включенный переключатель публичного IP — 3840 ₽/месяц. Цена и наличие в кабинете перед созданием подлежат проверке. На публичной странице указан минимальный первый платеж 2000 ₽. Источник: https://timeweb.cloud/services/vds-vps?location=ru . Новое платное размещение и передача базы выбранному хостеру требуют согласования с владельцем. Никакой VPS пока не куплен.

## Состав поставки

- `deploy/ru/compose.yaml` — приложение, HTTPS и служба обслуживания.
- `deploy/ru/Dockerfile` — сборка и запуск без root внутри контейнера.
- `server/sqlite-d1.mjs` — адаптер транзакций для SQLite.
- `server/import-snapshot.mjs` — перенос снимка D1 с проверкой целостности и внешних ключей; сессии и временные лимиты очищаются, пароли сохраняются.
- `server/backup.mjs` — согласованная онлайн-копия SQLite, включая WAL.
- `server/supervise.mjs` — завершение зависшего приложения для перезапуска контейнера.

Секреты, снимки базы и таблицы доступов в GitHub и Docker build context не включаются. Снимок содержит закрытые данные; передавать его можно только в согласованный аккаунт хостинга по SSH/SFTP.

## Развертывание после согласования

1. Создать российский VPS, установить актуальные обновления ОС и Docker Engine/Compose из официального репозитория. Для SSH проверить ключ хоста в консоли провайдера. Открыть снаружи 80/443; SSH ограничить доверенными адресами. Порт 3000 не публикуется. Проверить правила сети с учетом Docker.
2. Разместить исходники в `/opt/umnik`. В корне проекта выполнить:

```sh
node deploy/ru/init-env.mjs
# Открыть deploy/ru/.env в защищенном редакторе. NEWS_SYNC_TOKEN уже создан.
# GROQ_API_KEY оставить пустым до отдельной безопасной настройки.
docker compose -f deploy/ru/compose.yaml build
```

3. Предупредить студентов о коротком окне обслуживания, остановить запись на старой площадке и получить свежий полный снимок всех таблиц. Хранить его только в закрытом каталоге, права 0600. На момент подготовительного снимка было 155 пользователей, 154 назначения дисциплин, 15 новостей; эти числа не заменяют проверку свежего снимка при переносе.
4. Сначала восстановить базу в новом пустом каталоге, без запуска приложения:

```sh
sudo install -d -m 700 -o 1000 -g 1000 /opt/umnik-migration
# snapshot.json передан по SFTP с правами 0600, владелец UID 1000.
docker compose -f deploy/ru/compose.yaml run --rm --no-deps \
  -v /opt/umnik-migration:/migration app \
  node server/import-snapshot.mjs /migration/snapshot.json /app/data/umnik.sqlite
```

Повторный импорт в непустую базу отклоняется. Нельзя запускать пустое приложение до импорта, иначе оно может создать начальные записи. После импорта проверить число и содержимое строк и хеши паролей без вывода персональных данных в журнал. Хранить старую площадку до завершения приемки.

5. Запустить `app`, проверить readiness внутри контейнера и выполнить приемку на временном тестовом имени/маршруте. Непосредственно перед переключением DNS проверить, что после снимка на старой площадке не появились новые изменения. Если появились — повторить перенос в новую пустую базу.

```sh
docker compose -f deploy/ru/compose.yaml up -d app
docker compose -f deploy/ru/compose.yaml exec app node -e \
  "fetch('http://127.0.0.1:3000/api/health').then(async r=>{console.log(r.status,await r.text());if(!r.ok)process.exit(1)})"
```

6. В Beget заменить обе A-записи корня на один IPv4 VPS, заменить CNAME `edu` на A с тем же IPv4. Удалить только относящиеся к этим двум хостам конфликтующие AAAA, если они появились. MX, почтовые TXT и остальные записи сохранить. Старые записи и их значения находятся в отдельной локальной резервной копии DNS. Не подставлять чужой или примерный IP.
7. Запустить весь Compose. Caddy выдаст и будет продлевать сертификаты обоих доменов после поступления DNS на сервер. Не обходить предупреждения TLS. Проверить `/`, `/education`, оба симулятора, `/api/health`, вход администратора и вымышленного студента, сохранение/загрузку и отчеты.

```sh
docker compose -f deploy/ru/compose.yaml up -d
docker compose -f deploy/ru/compose.yaml ps
docker compose -f deploy/ru/compose.yaml logs --tail 80 app web maintenance
```

8. Выполнить проверку без VPN с российского домашнего и мобильного подключения. Проверка из облачного браузера этого не заменяет. Затем возобновить запись только на новом сервере. После приемки отключить публичную запись на старой площадке, чтобы разные адреса не сохраняли работы в разные базы.

## Эксплуатация и восстановление

`maintenance` создает копию при старте и затем ежедневно после 04:00 МСК; сохраняет 14 дней. Проверка новостей — при старте и ежедневно после 09:00 МСК, повтор после ошибки не чаще раза в 30 минут. Новости поступают в черновики. При перезапуске в один день возможна дополнительная копия/проверка. Состояние заданного ключа в интерфейсе не доказывает, что служба запущена: проверить журнал и фактическое время последней успешной проверки.

Копии в отдельном Docker volume защищают от ошибок приложения, но находятся на том же VPS. Для отказа диска/аккаунта необходима дополнительная копия вне сервера. Ее получатель и расходы согласуются отдельно. Нельзя заявлять, что внешнее резервное хранение уже настроено.

Для восстановления: остановить `app` и `maintenance`, сохранить текущую базу и WAL для расследования, проверить `PRAGMA integrity_check` выбранной копии, восстановить ее в **новый** каталог/volume, установить владельца UID 1000 и права 0600. Не подменять файл базы при работающем приложении и не смешивать копию с чужими WAL/SHM. Запустить приложение с новым volume, проверить вход, последние версии и отчеты; затем обслуживание. Не применять `docker compose down -v`: это удаляет постоянные данные и сертификаты.

Проверять свободное место, результат резервного копирования, срок сертификатов, остаток баланса и доступность с независимого российского подключения. Автоматическое внешнее оповещение об отказе пока не подключено. Groq необходимо отдельно проверить с нового сервера; платный обходной провайдер не включается автоматически. Известный прежний ключ имеет срок до 09.01.2027; его значение в поставке отсутствует.

## Выполненная проверка

Производственная сборка Next.js и сборка Sites/Vinext выполнены на Windows с Node 24.19. На вымышленных учетных записях выполнены 29 сценариев УМНИК и 43 сценария дисциплин/метрик через обработчики собранного приложения без сетевого слушателя. Дополнительно — 7 проверок origin, Secure cookie и отклонения поддельной облачной идентификации, а также транзакции и онлайн-копия SQLite. Сравнение восстановленного закрытого снимка: все записи 18 переносимых таблиц совпали; сессии и лимиты намеренно исключены.

Docker в локальной среде отсутствует. Сборку Linux-контейнера, выдачу публичного HTTPS, перезапуск после отказа и реальную доступность из России нужно проверить на согласованном VPS до окончательной приемки. Локальная проверка не является запуском российского хостинга.
